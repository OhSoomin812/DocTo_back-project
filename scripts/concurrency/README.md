# 예약 동시성 · 정원 · 권한 재현 스크립트

DocTo 백엔드를 로컬에 띄운 뒤 실제 API를 호출해 결함을 재현하고,
`fix/appointment-integrity` 수정 전후를 비교한 스크립트입니다.

## 환경
Docker Compose — PostgreSQL 16, Redis 7, Kafka 3.8, Spring Boot 3.4.5 (로컬 단일 인스턴스)
백엔드가 `http://localhost:8080` 에 떠 있어야 합니다. (Node 18+ 에 내장된 fetch 사용)

## 실행

```bash
# 같은 환자·같은 시간 예약 20건을 동시에 요청
node race.cjs 20 2026-10-20T10:00:00

# 정원 초과 확정 / 타 병원 관리자의 예약 상태 변경
# (예약 생성 뒤 출력된 appointment_id 를 인자로 전달)
node cap.cjs 2026-10-20T11:00:00 <id1> <id2> <id3>
```

## 측정 결과

| 상황 | 수정 전 | 수정 후 |
|---|---|---|
| 같은 예약 20건 동시 요청 (6회 반복) | 3·5·6·5·6·4건 저장 | 6회 모두 1건 |
| 정원 1명 의사의 같은 슬롯 2건 확정 | 200·200 | 200·400 (D_012) |
| 타 병원 관리자의 예약 상태 변경 | 200 | 403 (T_004) |

> 계정은 로컬 시드용 더미입니다 (`*.docto.local` / `Docto1234!`).
